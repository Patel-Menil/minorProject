# eICU Tabular Data Handoff

This document explains the structure and contents of the eICU tabular feature dataset. The dataset has been processed and engineered specifically to be used as input for a **Tabular Encoder** (such as an Autoencoder or MLP) in a multimodal deep learning pipeline.

## Data Organization

The dataset is partitioned by hospital to allow for distributed loading and cross-validation strategies. 
For each of the 208 hospitals, you will receive a file named:
`data/processed/hospitals/hospital_<id>/tabular/tabular_features.parquet`

Each row in the `.parquet` file represents a single, unique ICU patient stay (`patientunitstayid`). 

## Feature Schema

The tabular data represents the **static clinical context** of the patient upon admission, including demographics, chronic comorbidities, and baseline severity scores. There are approximately 70-80 columns per file.

### 1. Core Identifiers & Outcomes
*Note: Outcome columns are meant to be used as targets/labels, NOT as input features for the encoder.*
- `patientunitstayid`: Unique integer ID for the ICU stay.
- `hospital_expired`: Binary target (1.0 = died in hospital, 0.0 = survived).
- `icu_expired`: Binary target (1.0 = died in ICU, 0.0 = survived).
- `hospitaldischargeoffset` / `unitdischargeoffset`: Float targets representing Hospital and ICU Length of Stay (in minutes).

### 2. Demographics & Context
- `age`: Patient age (float). Ages > 89 have been capped at 90.0.
- `gender_Male`: Binary (1.0 = Male, 0.0 = Female/Unknown).
- `BMI`: Calculated Body Mass Index (weight in kg / height in m^2).
- `ethnicity_{Category}`: One-hot encoded columns for Caucasian, African American, Hispanic, Asian, and Other.
- `hospitaladmitoffset`: Time from hospital admission to ICU admission (minutes).
- `unitvisitnumber`: Number of ICU visits for this patient during this hospital stay.

### 3. APACHE IV Baseline Scores
- `acutephysiologyscore`, `apachescore`: Standardized baseline illness severity scores.
- `predictedicumortality`, `predictediculos`: APACHE IV benchmark predictions (useful for baseline comparisons).

### 4. Chronic Comorbidities & Day 1 Extremes (APACHE Pred Var)
- **Binary Flags (0.0 or 1.0)**: `aids`, `cirrhosis`, `diabetes`, `hepaticfailure`, `leukemia`, `lymphoma`, `metastaticcancer`, `immunosuppression`.
- **Day 1 Physiological Baseline (Floats)**: `verbal`, `motor`, `eyes` (Glasgow Coma Scale components), `pao2`, `fio2`, `creatinine`.

### 5. Diagnosis Phenotype (Multi-hot)
Extracted from `diagnosis.csv`, these represent the patient's disease burden at admission.
- `diag_{category}`: ~20 binary columns representing the top 20 most frequent top-level clinical diagnosis categories across the entire eICU database (e.g., cardiovascular, pulmonary, renal).
- `diag_other_count`: An integer/float count of how many diagnoses this patient had that fell *outside* the top 20 categories.

### 6. Home Medications (Multi-hot)
Extracted from `admissionDrug.csv`, this acts as a proxy for chronic disease burden prior to admission.
- `admitdrug_{drugname}`: ~20 binary columns representing the top 20 most frequent pre-admission outpatient drugs.
- `admitdrug_other_count`: An integer/float count of how many pre-admission drugs this patient had that fell *outside* the top 20 categories.

---
*Note: Any missing values in the feature engineering pipeline were imputed with `0.0`. You may choose to apply z-score normalization to the continuous float columns prior to model ingestion.*

## LLM Prompt Context

*Copy and paste the prompt below to your LLM/Agent to get them up to speed immediately.*

```text
You are assisting me with developing a Tabular Encoder (an Autoencoder or MLP) for a multimodal deep learning model using the eICU Collaborative Research Database. 

I have a dataset of `.parquet` files, each containing engineered static tabular features for ICU patients (1 row per ICU stay). The data includes demographics, APACHE IV baseline scores, chronic comorbidities, and multi-hot vectors representing admission diagnoses and home medications. Outcome columns like `hospital_expired` and `unitdischargeoffset` are also present to be used as labels. Missing values have been imputed with 0.0.

My goal for this tabular branch is to learn a dense, latent tabular embedding for each patient. This tabular embedding will later be concatenated with a temporal embedding (generated by an LSTM processing a separate time-series dataset) for downstream mortality and LOS prediction tasks.

Please write a PyTorch `Dataset` class to load these `.parquet` files, separate the input features from the outcome targets, apply standard scaling to the continuous features, and build a PyTorch `nn.Module` (like an MLP Autoencoder) capable of projecting these ~80 input features into a latent embedding space of size 32 or 64.
```
